# v1.0.0 正式发布与全仓库文档更新设计方案

## 1. 背景与意图 (Intent & Why)

`astrbot_plugin_playwright_tools` 经过多轮内部特性重构（四大复合工具收敛、内联交互 Markdown 与 ARIA 双阅读器、WebUI 独立 MD3 运维控制台、Playwright 原生交互与 Camoufox 解耦适配器），现已进入成熟稳定期，准备进行**正式公开发布**。

为了向终端用户与 Bot 管理员提供一流的开箱体验，需将版本号正式对齐为 **`v1.0.0`**，全面清理与修正仓库内所有过时与失真的旧信息（四大工具演进、新增配置项等），并将 `README.md` 重构为以用户为首要阅读对象的排版结构。

---

## 2. 目标与非目标 (Goals & Non-Goals)

### 2.1 目标 (Goals)
1. **版本号统一升级为 `v1.0.0`**：
   - 更新 `metadata.yaml` 中的 `version: v1.0.0`。
   - 更新 `main.py` 插件注册 `@register(..., "v1.0.0")`。
   - 同步更新测试用例 `tests/test_plugin_main.py` 中的版本号断言。
2. **`CHANGELOG.md` 重组**：
   - 顶部追加 `## [v1.0.0] - 2026-11-21 (正式公开发布)`，汇总插件完整能力。
   - 将原预发布内部迭代的 `v2.x.x` 版本号系统性调整为 `v0.x.x` 内部预览演进（如 `v0.2.1`、`v0.2.0` ...）。
3. **`README.md` 用户导向排版重构**：
   - **第一部分：特性亮点**：突出四大复合工具、Ref ID 精准定位、Camoufox 防反爬、Markdown/ARIA 双阅读模式、多租户隐私隔离、统一 MD3 控制台。
   - **第二部分：安装指引**：Python 3.10+ 环境、Camoufox 与 Playwright 依赖安装、浏览器内核初始化命令。
   - **第三部分：插件指令与配置**：
     - 用户/管理员 `/browser` 完整指令表格；
     - WebUI 配置（按安全、运行时、浏览器引擎、截图媒体、存储审计五大业务分组，补齐 `content_extraction_mode`、`mask_password_inputs`、`browser_executable_path`、`page_chunk_char_limit` 等所有项）。
   - **第四部分：内置 SKILL 介绍**：介绍插件随附的 `playwright-tool` SKILL，说明 AI 如何获得网页浏览与交互经验。
   - **第五部分：大模型工具规范**：全面更新为四大独立工具（`pw_page`、`pw_read`、`pw_interact`、`pw_media`）的动作与入参规范。
   - **第六部分：系统架构与延伸文档**：链接至 `docs/ARCHITECTURE.md`。
4. **关联文档全面更新**：
   - `skills/playwright-tool/SKILL.md`：更正为四大工具体系（独立 `pw_read`，移除旧 `pw_page(action='read')`），更新引导大模型阅读正文与元素定位的策略。
   - `docs/ARCHITECTURE.md`：更新分层架构 Mermaid 图与文字说明，加入 `pw_read` 门面及 `core/readers/`（InlineMarkdownReader / AriaSnapshotReader）组件。
   - `AGENT.md`：更新项目目录（加入 `skills/`、`tests/`）、当前四大工具说明与单元测试规范。
5. **测试保障**：运行 `python -m unittest discover tests`，确保全部 167+ 单测 100% 绿灯通过。

### 2.2 非目标 (Non-Goals)
- 不处理 `docs/superpowers/` 内的历史规格与计划文件。
- 不删除 `docs/old/` 目录（保留作为历史设计草稿）。
- 不引入任何功能性业务代码修改（仅版本号与文档更新）。

### 2.3 反目标 (Anti-Goals)
- 严禁在公开文档中遗留过时的“三大工具”描述或 `pw_page(action='read')` 伪签名。
- 严禁在文档中使用绝对化吹嘘词汇（如“彻底解决”、“根治”等），实事求是。

---

## 3. 约束 (Constraints)

- **版本号格式**：必须带 `v` 前缀（`v1.0.0`）。
- **向后兼容与测试**：所有单元测试必须保持 100% 绿灯通过，不得产生测试回退。
- **文档规范**：严格遵循 `AGENT.md` 中的文档编写规范（凝练简洁、不啰嗦、不包含绝对化词汇）。

---

## 4. 方案选型 (Approaches Considered)

- **方案 A（已采纳）：用户导向全景分层重组**
  - 将 README 结构设计为以普通用户与运维管理员由浅入深的逻辑（亮点 → 安装 → 指令配置 → 内置技能 → AI工具规范 → 架构），并在全仓库同步更新 SKILL、ARCHITECTURE、AGENT 与 CHANGELOG。
  - **权衡**：信息完备、查阅高效，无论是普通使用者还是接入大模型的开发者均可快速获取所需信息。
- **方案 B（放弃）：极简精炼型重构**
  - README 仅保留亮点与安装，AI 工具细节全部隐藏并委托给外部文档。
  - **放弃原因**：用户在 GitHub 首页无法直观评估大模型具备的各项具体网页交互能力，增加跳转成本。
